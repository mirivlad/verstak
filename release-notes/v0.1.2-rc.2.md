## Highlights

- The worklog is a document. Journal entries live in the Deal they belong to, as one ordinary Markdown file per month — `Клиенты/Ромашка/Журнал/2026-07.md` — instead of a JSON blob under `.verstak` that no editor opens and sync skips by design. The prose is yours: an entry typed into the file by hand is a journal entry, and correcting "45 мин" to "90 мин" there is the truth. Worklogs written before this are copied into their Deal at first read; the old copy is left exactly where it is.
- The Journal reports. A period joins the filters — this week, this month, last month, this year, exact dates — and the report counts what is in view: the total, what is billable and what is not, then each Deal with the most time first and its work under it. Two buttons write it into the vault, Markdown for reading and sending, CSV for whatever produces the invoice, and the file opens once written.
- Todos travel between devices. A plugin can declare which of its data is a list of records; that list is then carried through the same operation log as files, one operation per record. Two devices adding different todos keep both, rather than one list overwriting the other.
- A Deal that shows a tool is visible to that tool. A Deal made by hand or carried in by an import has no tool list, and the workspace host reads that as "nothing is restricted" — but the plugin API read it as "no tools at all". On a vault whose Deals came from a DokuWiki import that was every Deal: the global Journal listed nothing and offered no Deal to write an entry into.
- A bug report can carry facts. Every run writes a session log, not only the ones started with `--debug`; a panic writes its own report; and Settings → Diagnostics saves a plain-text report with the build, the plugin statuses and the tail of the log. The vault's contents, your secrets and your sync key are never in it.
- Every plugin package carries checksums, and the application verifies them when it finds the plugin. A file that arrives changed, missing or extra makes the plugin degraded with the reason named, instead of the plugin behaving oddly and nobody knowing why. It is a checksum, not a signature: it catches damage and staleness.
- `scripts/release-smoke.sh` checks a built release — binary, every packaged plugin against its own checksums, artifacts and their sizes, SHA256SUMS, release notes — and `docs/RELEASE_CHECKLIST.md` carries what only a person can check.

## Главное

- Журнал работ — документ. Записи лежат в самом Деле, по обычному Markdown-файлу на месяц: `Клиенты/Ромашка/Журнал/2026-07.md`, а не в JSON-блобе под `.verstak`, который не открывает ни один редактор и мимо которого синхронизация проходит по устройству. Текст принадлежит вам: запись, написанная в файле руками, — полноценная запись журнала, а правка «45 мин» на «90 мин» — это решение, а не ошибка. Журналы, написанные раньше, переносятся в Дело при первом чтении; старая копия остаётся на месте.
- Журнал считает. К фильтрам добавлен период — неделя, месяц, прошлый месяц, год, точные даты, — а отчёт подводит итог по тому, что в нём видно: всего, к оплате и не к оплате, затем Дела, начиная с того, на которое ушло больше времени. Две кнопки сохраняют его в vault: Markdown — читать и отправлять, CSV — для того, что выставляет счёт; сохранённый файл сразу открывается.
- Задачи переносятся между устройствами. Плагин объявляет, какие его данные — список записей, и этот список едет через тот же журнал операций, что и файлы, по операции на запись. Две машины, добавившие разные задачи, сохраняют обе, а не затирают список друг друга.
- Дело, которое показывает инструмент, теперь этому инструменту видно. У Дела, созданного руками или приехавшего из импорта, нет списка инструментов, и оболочка читает это как «ничего не ограничено», а плагинный API читал как «инструментов нет вовсе». На vault, где Дела пришли из DokuWiki, это были все Дела: глобальный Журнал не показывал ничего и не предлагал Дело, куда записать.
- Отчёт об ошибке теперь содержит факты. Лог пишется при каждом запуске, а не только с `--debug`; падение оставляет собственный файл; «Настройки → Диагностика» сохраняет текстовый отчёт со сборкой, состоянием плагинов и хвостом лога. Содержимое vault, секреты и ключ синхронизации в него не попадают.
- Каждый пакет плагина несёт контрольные суммы, и приложение проверяет их при обнаружении плагина. Изменённый, пропавший или лишний файл переводит плагин в состояние degraded с названной причиной, вместо странного поведения без объяснений. Это контрольная сумма, а не подпись: она ловит повреждение и устаревшую копию.
- `scripts/release-smoke.sh` проверяет собранный релиз — бинарник, каждый пакет плагина по его контрольным суммам, артефакты и их размеры, SHA256SUMS, release notes, — а `docs/RELEASE_CHECKLIST.md` держит то, что может проверить только человек.

## Fixed since rc.1 / Исправлено после rc.1

- Opening settings from the sync status bar left a window where nothing could be selected: the request was treated as a rule that held for as long as the window was open, and the section it asked for did not exist. A plugin asking for its own settings without naming a panel now lands on the panel it has, once.
- Открытие настроек по «Не настроено» в строке состояния оставляло окно, в котором ничего нельзя было выбрать: запрос действовал всё время, пока окно открыто, а раздел, который он называл, не существовал. Плагин, запрашивающий свои настройки без имени панели, теперь попадает на ту панель, которая у него есть, — один раз.

## Packages / Пакеты

A Debian package and an AppImage for Linux, with the matching official plugins bundled. The browser extension is unchanged in this build.

Debian-пакет и AppImage для Linux с соответствующим комплектом официальных плагинов. Расширение браузера в этой сборке не менялось.
