# Verstak v0.2.11

## Исправления синхронизации

- При первоначальной синхронизации клиент сначала анализирует удалённую историю файлов. Уже завершённые цепочки создания, перемещения и удаления файла не воспроизводятся поверх самостоятельных локальных файлов. Неоднозначные случаи по-прежнему считаются конфликтами и не перезаписываются автоматически.
- Первичная загрузка поддерживает создание организационных папок рабочих областей с сохранением серверных UUID. Совпадения путей с другими локальными сущностями остаются защищёнными от перезаписи.
- Повторное подключение устройства к тому же серверу и хранилищу больше не обнуляет позицию успешно завершённой синхронизации и не сбрасывает её первоначальное согласование.
- Сообщение об ошибке авторизации теперь предлагает проверить логин, пароль или привязку устройства, вместо того чтобы ошибочно утверждать, что устройство отозвано.
- Добавлены регрессионные тесты для исторических перемещений, сохранения локальной очереди, повторной авторизации и создания папок.

**Внимание:** если в хранилище есть несинхронизированные изменения, сохраните его резервную копию целиком, включая скрытый каталог `.verstak`, перед повторной попыткой синхронизации. Конфликты, которые невозможно согласовать без риска потери данных, по-прежнему останавливают процесс.

## Synchronization fixes

- During initial sync, examine the server file-operation history and skip fully obsolete create/move/delete lifetimes instead of replaying them against unrelated existing local files. Ambiguous conflicts still fail safely.
- Support UUID-preserving organizational folder creation during remote synchronization without replacing existing unrelated local folders.
- Keep a completed sync cursor and bootstrap status when pairing again with the same server and remote vault.
- Clarify authorization failures, distinguishing them from definite device revocation.
- Add regression coverage for history replay, pending operations, reconnects, and folders.

**Back up the complete vault, including `.verstak`, before retrying synchronization with outstanding local changes.**
