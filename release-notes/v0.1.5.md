## Highlights

- Projects has been redesigned into a native Verstak master-detail workspace instead of a compact dashboard made of equal cards. The project list is optimized for scanning, the detail area uses the available space, and Overview focuses on useful project context, milestones and recent changes.
- Linking a project to a Deal no longer exposes or asks the user to type an internal filesystem path. Projects now uses a searchable hierarchical Deal picker backed by the public read-only workspace tree, preserves parent context for duplicate names, and stores stable Deal identity alongside the canonical path.
- Existing Projects data remains usable. Projects safely resolves v0.1.4 `workspaceRootPath` links to stable Deal IDs when possible, preserves unresolved legacy links without destroying them, and only writes a new canonical link after an explicit safe selection.
- Project history now records meaningful changes such as status and priority transitions, Deal linking, milestone changes and links instead of repeating generic “project changed” entries.
- Tasks, Notes, Files and Activity remain optional provider integrations. Missing providers degrade to compact explanatory states and never make the project itself unusable.

## Главное

- Projects переработан в нормальный для Верстака интерфейс master-detail вместо маленькой панели и набора одинаковых карточек. Список проектов рассчитан на быстрый просмотр, правая часть использует доступное место, а «Обзор» показывает действительно полезный контекст, этапы и последние изменения.
- Привязка проекта к Делу больше не показывает внутренний путь файловой системы и не требует вводить его руками. Теперь используется иерархический поиск Дел через публичное read-only дерево workspace: одинаковые имена различаются по родительскому контексту, а вместе с каноническим путём сохраняется стабильный ID Дела.
- Данные Projects из v0.1.4 остаются совместимыми. Старый `workspaceRootPath` безопасно сопоставляется со стабильным ID, когда это возможно; неразрешённая старая ссылка сохраняется и не затирается; новый канонический link записывается только после однозначного выбора.
- История проекта теперь содержит осмысленные события: смену статуса и приоритета, привязку Дела, изменения этапов и ссылок — вместо повторяющегося «проект изменён».
- Задачи, Заметки, Файлы и Активность по-прежнему подключаются как необязательные провайдеры. Отключение любого из них не ломает сам проект и даёт компактное понятное degraded-state сообщение.

## Under the hood / Под капотом

- The SDK exposes optional `workspaces.tree()` as a generic read-only platform contract for the full user-visible Deal/folder hierarchy, while `workspaces.list()` keeps its existing plugin-filtered semantics.
- Desktop exposes that contract through the normal `createPluginAPI()` path, so mounted views and background `activate()` handlers receive the same API without a Projects-specific privilege or direct vault walk.
- Projects 0.2.0 continues to use provider-independent `api.capabilities.invoke(...)`; capability results are handled through the normal `PluginCommandResult` wrapper.
- Regression coverage includes v0.1.4 migration, unresolved links, nested and duplicate Deal names, Deal persistence/reopen, optional-provider degradation, dark select styling and narrow-layout behavior.

## Packages / Пакеты

Debian package and AppImage for Linux, plus the Windows x64 ZIP, with the matching official plugins bundled. The browser extension and sync server are unchanged in this release.

Debian-пакет и AppImage для Linux, а также ZIP для Windows x64 — с соответствующим комплектом официальных плагинов. Расширение браузера и сервер синхронизации в этом релизе не менялись.
