# Verstak v0.1.5

> Historical release note. The nested Project scope described below was
> superseded by the Deal-only model; see [`docs/DEAL_ONLY_SCOPE.md`](../docs/DEAL_ONLY_SCOPE.md).

## Highlights

- Projects now follows the Verstak hierarchy: **Deal → Project → project resources**. A Project is focused work inside one Deal, not a second Deal-like container.
- The global Projects item is a full-width portfolio of every project across Deals. Cards show state, Deal, milestone progress and the next milestone without opening another nested sidebar.
- Opening a portfolio card switches to its Deal and opens that exact project. The shell now exposes `navigation.openWorkspace(...)` so plugins can navigate by stable Deal ID and pass opaque tool state without shell-private DOM choreography.
- Inside a Deal, Projects shows the selected project directly, with Overview, Milestones, Tasks, Notes, Files, Activity and Links. There is no second project sidebar.
- Tasks, Notes and Files created from a project carry `projectId`. Project tabs show only that project's resources, while the normal Deal-level provider views still show all resources in the Deal.
- Projects must belong to a Deal. New projects cannot be saved unlinked. Legacy orphaned project records remain readable and can be repaired by choosing a valid Deal.
- The hierarchical Deal picker uses stable Deal identity, preserves parent context for duplicate names, and no longer clips below the project dialog.
- Project history records meaningful changes and powers the project Activity tab without coupling Projects to a specific Activity provider implementation.

## Главное

- Projects теперь следует иерархии Верстака: **Дело → Проект → ресурсы проекта**. Проект — это конкретная работа внутри одного Дела, а не ещё один контейнер, похожий на Дело.
- Глобальный пункт «Проекты» стал полноширинным портфелем всех проектов из всех Дел. Карточки показывают состояние, Дело, прогресс этапов и следующий этап без дополнительного вложенного сайдбара.
- Нажатие на карточку переключает Верстак в нужное Дело и открывает именно этот проект. Для этого shell получил публичный `navigation.openWorkspace(...)` с устойчивым ID Дела и передачей состояния целевому инструменту.
- Внутри Дела Project сразу показывает выбранный проект: Обзор, Этапы, Задачи, Заметки, Файлы, Активность и Ссылки. Второго списка проектов слева больше нет.
- Задачи, заметки и файлы, созданные из проекта, получают `projectId`. Вкладки проекта видят только свои ресурсы, а обычные вкладки Дела по-прежнему видят всё содержимое Дела.
- Проект обязан принадлежать Делу. Новый проект нельзя сохранить без связи. Старые orphan-записи не уничтожаются и могут быть восстановлены выбором существующего Дела.
- Иерархический picker Дел использует стабильный ID, показывает родительский контекст для одинаковых имён и больше не обрезается границами диалога.
- История проекта хранит осмысленные изменения и используется вкладкой «Активность» проекта без жёсткой привязки к конкретной реализации Activity-плагина.

## Under the hood / Под капотом

- SDK: `workspaces.tree()` plus typed `navigation.openWorkspace(...)`.
- Todo stores `projectId` directly; Notes and Files keep provider-owned synchronized scope metadata so the visible Deal filesystem is not polluted with technical project directories.
- Scope metadata follows Notes/Files through rename, move and trash operations; safe legacy data remains readable.
- Regression gates cover project scoping, portfolio navigation, Deal picker duplicates/orphans, provider degradation, SDK types, bridge routing and visual screenshots.

## Packages / Пакеты

Debian package and AppImage for Linux, plus the Windows x64 ZIP, with the matching official plugins bundled. The browser extension and sync server are unchanged in this release.

Debian-пакет и AppImage для Linux, а также ZIP для Windows x64 — с соответствующим комплектом официальных плагинов. Расширение браузера и сервер синхронизации в этом релизе не менялись.
